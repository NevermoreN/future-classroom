## 1. 已确认需求与本轮默认值

已确认：首次使用创建主管理员；主管理员管理全部内容；创建任课老师填写任教科目；按课表自动调用对应老师科目的布局、配置和老师资料文件名列表；统一ProgramData存储；学校先建基础科目，再在课表中选择；顶部提供临时换课；课间、午休不随科目改变；所有教师管理员可通过Web共同维护同安装学校范围全部当天提醒，Web底部有显眼入口；提醒只保留到当日23:59:59，次日清空并移除磁贴，新发送后恢复；所有磁贴自适应补位。最新指令明确：本地程序不提供提醒修改/发送入口。

为使开发无歧义，本轮采用以下默认值，属于产品设计决策：

- 首版每台白板绑定一个学校、一个当前班级，数据结构保留classId；不据此新增多校集中服务。学校基础科目可包括语文、数学、英语、政治等，由主管理员维护，不硬编码这四门。
- 任课老师可教多个科目、多个已授权班级，创建时至少勾选一项任教科目及一个班级。主管理员创建页也有任教科目字段，可明确选择“不任课”；兼任教学时在建好科目后关联，不给普通老师“不任课”选项。
- 每个班级/科目可有多名老师；课表格需保存实际任课老师。只有一个有效候选时可自动选定，多人时必须明确选择，不能按用户名/上传时间猜。
- 教师管理员可写本人作业、本人科目资料、全部学校内当天提醒，并可发起本人任教且本白板绑定班级的语音播报；组件/布局只允许全局主管理员，旧授权立即失效；教室桌面临时换课/恢复原课为公开本机操作，不要求应用登录，Web不开放换课。
- 临时换课只影响当前实际日期、当前有效课时；到该节结束失效，不延长课时、不调整基础周表，也不自动把被替换的课挪到别处。
- 今日提醒为班级当天公共内容，同安装学校范围所有教师管理员与全局主管理员均可通过Web编辑或清空；采用版本冲突检查，不默默覆盖别人刚保存的内容。主管理员也通过Web维护提醒，本地管理权限不绕过渠道限制。

## 2. 首次初始化、登录与授权

部署先准备本机数据根及Windows权限，然后进入应用初始化：

```text
UNINITIALIZED → 创建主管理员账号/口令/恢复码
→ 录入学校与班级 → 维护基础科目 → 创建任课老师并分配班级/科目
→ 填学期课表与作息 → 绑定任课老师 → 配置公共布局及各科目布局
→ 预览 → 开始使用
```

主管理员一经成功创建即关闭公开创建入口；后续只完成设置，不因向导中断再次开放主管理员注册。无默认密码、无自助认领任教学科、无远程自助提权。保留至少一个有效主管理员；首版默认一名，交接需要当前主管理员再验证及原子转移，不允许先删除最后一名主管理员。凭据损坏进入修复状态，不视为首次安装。

账号有全局主管理员、教师管理员、用户三个应用角色，与Windows账号分离；任教关联只适用于教师管理员及兼任教学的全局主管理员。主管理员本地创建姓名、唯一登录名、初始口令、任教班级与科目，教师首次登录强制改初始口令；教师不能修改自己的角色或任教范围。口令复用既有KDF/盐/限速机制，每账号独立；本地工作台与Web会话独立，锁屏/离开本地工作台立即失效本地会话，远程授权仍按其自身有效期判定。

网页配对须绑定已存在的同一principalId。不得只填“王老师”就成为王老师，也不能把配对成功自动变成全校科目权限。任教关系更改/账号停用递增授权代次，撤销该范围内未提交任务；重新授权不自动提交旧草稿。

| 能力 | 全局主管理员 | 教师管理员 | 用户/未登录只读 |
| --- | --- | --- | --- |
| 科目/账号/课表/校历/系统、全部组件/布局/profile外观 | 全部 | 拒绝 | 拒绝 |
| 资料与作业内容 | 全部 | 仅本人且有效任教范围 | 拒绝写 |
| 当前发布文件查看/本地打开 | 允许 | 允许 | 当前课堂只读 |
| 今日提醒 | 仅Web，同安装学校全部 | 仅Web，同安装学校全部受管班级，不限作者 | 桌面只读 |
| 教室桌面临时换课/恢复原课 | 无需登录，直接操作 | 无需登录，直接操作 | 无需登录，直接操作 |

“主管理员管理全部内容”是应用能力，不等于自动获得Windows提权。系统目录初始化、证书配置等仍走受控部署工具。

## 3. 数据与持久化契约

| 对象 | 主键/必需字段 | 约束 |
| --- | --- | --- |
| SchoolSubject | subjectId、schoolId、name、enabled、revision | ID稳定，学校内规范化名称唯一；重命名不改变引用 |
| UserAccount | principalId、loginName、displayName、role、enabled、credentialRef、authGeneration | 创建角色仅主管理员可授予；不存明文口令 |
| TeachingAssignment | assignmentId、principalId、classId、subjectId、enabled、revision | 账号、科目和班级均存在且有效 |
| SubjectProfile | profileId、classId、subjectId、teacherId、layout、displaySettings、resourceRefs、revision | 每组班级/科目/老师一个有效配置；布局只允许全局维护，教师只写本人内容 |
| CourseCell | subjectId、teacherId或显式未分配、备注 | 科目从目录选择；老师必须是该班该科目有效任课人 |
| LessonInstanceKey | classId、actualDate、ResolvedScheduleVersion（实际/来源学期及映射修订）、begin/end | 使用实际授课日期及有效课表，不用补课来源日期代替今天 |
| LessonOverride | overrideId、lessonInstanceKey、targetSubjectId、targetTeacherId、actorId、revision、createdAt、expiresAt、status | 一个课时最多一条当前有效覆盖；expectedRevision裁决并发 |
| SharedReminder | classId、actualDate、expiresAt、text、revision、lastActorId、updatedAt、status | 纯空白归一为空，仅Web写；次日失效并清除活动正文 |
| HomeworkEntry | homeworkId、classId、actualDate、subjectId、ownerTeacherId、revision、text、lastActorId | 教师仅改本人且有效任教范围；同科多老师独立条目/注明老师；不可整班覆盖 |
| SceneSnapshot | sceneGeneration、lessonKey、scheduledSubject、effectiveSubject、teacherId、profileRevision、reminderRevision、layoutRevision | 不可变，一次切换完整布局/设置/资料；不含附件字节和原生句柄 |

本地、Web命令在可信适配层建立actor；客户端传的teacherId、subjectId、profileId只是目标，不是授权证据。提交前校验关系、资源所属范围、当前权限代次与expectedRevision；预览、下载、缩略图和历史版本读取同样鉴权，不只保护写入。

### ProgramData目录

用户所述“programedata”按Windows标准 **ProgramData** 落实。使用 `SHGetKnownFolderPath(FOLDERID_ProgramData)` 解析真实路径，通常为 `C:\ProgramData`，不硬编码C盘。官方依据：[Known Folder定义](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)、[获取路径API](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath)。

```text
%ProgramData%\FutureClassroom\
  state\classroom.db           # 配置、账号、科目、任教关系、课表、布局、资料索引、提醒、修订
  resources\teachers\          # 老师ID/科目ID/资料ID/版本，受控资料原件
  launches\                    # 有界打开副本；课堂文件列表不生成缩略图
  staging\                    # 有界临时上传；成功/失败/过期后回收
  backups\                    # 经明确操作产生的备份
  logs\                       # 脱敏、有配额
  runtime\                    # 数据根锁与恢复操作记录
```

配置与布局以数据库版本化记录为权威，不同时维护另一套可任意写入的JSON配置。资源文件由数据库关联teacherId/subjectId/classId；分目录或猜不到的文件名都不代替访问控制。网页只经鉴权资源端点取图，不把ProgramData作为静态根。

部署工具创建本项目子目录，给固定部署Windows账号最小必要读写权限，SYSTEM/系统管理员按维护需要保留；不对整个ProgramData改权限、不授予Everyone写权限。日常进程低权限运行，教师用应用账号经程序上传，不直接写Windows目录。ACL在创建/复制/迁移后读回核对，参见[微软文件安全与访问权限](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。同一个Windows账号能修改其获授文件的边界继续保留，应用账号不构成OS沙箱。

DPAPI继续用固定部署账号作用域，密文可以存于ProgramData但不因此变成任意Windows用户可解密。切换部署Windows账号须单独走凭据重新绑定和目录授权交接，不能仅复制密文。原LocalAppData数据迁移：停写→一致备份→受控复制到目标→核验引用与ACL→原子标记迁移完成→重新打开；失败保留源并停止迁移，不形成双写。首版卸载默认保留学校资料，明确选择清除且有权限才删除本项目数据；升级不清空资料。

## 4. 文件名列表与科目布局（文件名显示）

课堂资料只显示当前实际任课老师目录的文件名，成功加入的最新文件在最上；点击由本机已有软件打开。教师管理员在本人任教范围添加/删除，全局主管理员可管理全部，用户只查看/打开当前已发布资料。资料目录不采用人工封面或预览图，原独立图片磁贴保留。

布局保存文件列表的位置、尺寸、行距、字号、可见条数及自适应约束，不逐文件拖拽缩略图或手工排序。文件目录与资料新增序号由M05/M06管理，profile引用folderId；M16只选择对应老师的目录，M17处理本地打开。布局不能移动/遮住公共保护区。作业仍汇总当天全科，提醒仅Web写。

详细目录、文件类型/容量、倒序、增删、打开副本与错误规则见[三级权限与文件夹手册](08-三级权限与教师文件夹打开.md)，不再执行旧的“资料卡不能打开”限制。

## 5. 自动场景解析与原子切换

```text
系统时间/唤醒/课表或校历提交/科目配置提交/临时换课
→ 取同一组生效修订 → 已有教学日和课时状态解析
→ BREAK：使用公共课间视觉，资料保留上一课最终有效老师目录
→ 其他非COURSE：公共午休/活动/空闲布局，不套科目布局
→ COURSE：基础subjectId+teacherId → 有效当前节覆盖 → 目标profile
→ 合并受保护公共组件/当天提醒/全科作业
→ 一次发布SceneSnapshot → 前台策略允许才无激活更新
```

课间和午休的时长、计时规则及公共布局保持原方案；临时换课不改变LessonState的时间区间。课时结束切回公共视觉；有效课间仅保留上一课实际老师资料，下一节开始再按有效课程切目录。没有有效profile、老师未分配或资料损坏时使用中性的该节科目占位/公共默认内容并提示配置缺失，新课程不能残留上一科资料，也不借用另一位老师的配置；已确认课间保留目录不属于此错误分支。

只读取当前profile及有界当前老师目录的文件名/ID索引，不为课堂列表生成或预取缩略图；不为所有老师常驻窗口/线程/全目录缓存。切换带sceneGeneration及资源准备代次，迟到的上一节/旧profile结果丢弃。目录读取/配置失败不混合“语文布局+数学文件”；渲染整包采用有效新快照或中性占位。已提交资料仍保留，不因尚未上屏回滚。

## 6. 顶部临时换课

顶部固定按钮“临时换课 ▾”，旁边显示“当前：数学 · 王老师”。任何人点击后直接展示学校全部启用科目供选择，不弹登录、口令或身份验证。若选择科目有多个该班老师，须再选任课老师；只有一名自动选，无老师允许明确确认“暂未分配，使用默认布局”，不静默借用他人配置。

提交带当前LessonInstanceKey、覆盖expectedRevision和目标科目/老师；提交点再次读取系统时间与课表/校历版本。到点已下课、表已变化或当前不是有课程的COURSE行则拒绝 `LESSON_CONTEXT_CHANGED`，不让迟点操作改到下一节或把课间变成上课。休息、午休、活动、无课或待确认教学日时入口显示原因且不可提交。

生效标注“临时：语文 · 原数学 · 仅本节有效”，当日课表仅当前格显示原课与临时课，基础周表不修改。可“恢复原课”；同课时再次选择生成覆盖新修订，不叠加多层。两人同时换课，旧修订被拒绝。任何操作者均遵守当前课时及修订，不因公开入口而覆盖较新的提交。

有效覆盖持久化，程序在该节内重启可恢复；退出该节、课表/校历版本变化、目标科目停用或目标任教关系失效则终止覆盖并重算。时钟回拨不能复活已终止覆盖；活动记录保留至有界审计期，不能按“当前时间又进入老区间”重建已失效覆盖。

## 7. Web今日提醒、日终清空与全部磁贴自适应

今日提醒**只能在Web修改、发送或清空**。教师Web各页底部固定一个显眼的“管理今日提醒”按钮，手机适配安全边距并为内容预留高度，不能遮挡表单或发送按钮。点击进入可选受管班级的今日提醒页，显示本机当天日期（只读）、正文、发送/清空按钮、最后修改人、版本及“有效至今日23:59:59”。主管理员同样用Web，不增设本地管理员绕过入口。桌面只显示提醒，本地工作台不提供提醒编辑表单。

本地来源提醒变更命令在可信origin校验阶段拒绝 `CHANNEL_NOT_ALLOWED`；不只移除按钮。Web鉴权后校验启用教师/全局角色、同安装学校范围与提醒expectedRevision。教师可改/清空其他老师保存的受管班级提醒，元数据审计可查；不保留可恢复的提醒正文历史。日期以白板实际本机日历日为准，不跟随补课来源日期，客户端不能传入未来日期或延长期限。

接纳及提交时都读取本机当前日期；到期边界采用次日00:00:00（排他上界），即当日23:59:59仍可见。跨午夜才到达的昨日草稿返回 `REMINDER_DAY_CHANGED`，保留为浏览器未发送草稿并让老师主动核对，不自动当作第二天新提醒。日终任务把旧提醒标记EXPIRED并清除活动正文；调度器跨日、启动、唤醒及每次读取都检查有效期，因此关机过夜或错过定时任务也不会显示昨日提醒。已到期标记与日期水位持久化，系统时钟回拨不能复活旧提醒。

若跨日清理遇到磁盘不可写，仍按expiresAt/实际日期隐藏，不等写成功才隐藏；恢复可写后重试物理正文清理。日志/结果记录不保存完整提醒正文；备份是独立历史快照，但恢复必须再次过滤到期提醒，不能把旧提醒重新激活。日期与到期状态进入统一快照，避免先显示过期提醒再异步删除的闪回。

提醒可见条件为：开关启用、存在当天非空有效正文、展示前台策略允许。空字符串、纯空白、清空或到期均派生 `reminderVisible=false`。移除提醒磁贴及其间距，课表吸附到上方锚点；新发送有效非空提醒后恢复磁贴，课表下移。空状态仅在Web编辑器显示，不占桌面框。

**全部磁贴自适应**：公共时钟、日期倒计时、课堂资料、作业、提醒、课表等统一使用响应式网格/流式布局，声明顺序、最小/最大逻辑宽高、优先级、可伸缩方向和文本策略。按可用区域、DPI、内容量及可见组件重算，隐藏/到期的任意磁贴不占位。窄屏合并列，宽屏保留左右区；图像等比缩放、文字换行，允许交互的正文可分页；纯展示课表换行/限高，超限明确容量诊断且不生成翻页输入，不无限缩小到不可读或挤出任务栏。布局编辑保存约束和锚点，磁吸结果为派生值；全局配置的科目布局同样遵守保护区和约束，教师不能修改。内容量超预算时显示明确截断/分页提示，不用每秒动画解决溢出。

所有补位在一个SceneSnapshot中完成，保留当前学校/老师/科目上下文；不要边隐藏边逐个移动造成短时重叠。无持续动画，不逐次保存自动坐标。PPT隐藏期间只更新状态，返回桌面时直接用当前有效提醒与布局。

顶部“临时换课”是独立、小范围输入窗口，仅按钮矩形接受点击/触摸；其余透明空隙和资料展示区域继续穿透。不设置本地“编辑提醒”按钮。临时换课菜单和选择窗口只由用户主动打开，无需应用登录或身份验证；仍遵循桌面前台与操作系统会话可用性策略，PPT/其他应用前台时关闭或隐藏。打开本地科目工作台时展示层按既有设置窗口规则暂时隐藏。
