## 1. 首版范围与部署条件

首版页面：已有教师账号绑定/配对、本人任教科目资料、本人今日作业、文字/图片发布与结果、撤销、设备状态，以及**仅Web可写**的班级今日提醒，以及向授权任教班级发起的按住录音语音播报。各页底部固定显眼“管理今日提醒”按钮并预留内容高度/手机安全边距。无远程基础课表、学校科目/账号角色、校历、自启动、服务端授权凭据或主管理员口令写接口；这些由本地主管理员设置管理。

办公室到白板可达、固定访问地址/内部DNS、可信证书和项目专属防火墙规则属于部署前提。校外需已有校园VPN等可达通道；白板关机无可靠待投，不能把浏览器草稿当已送达。

## 2. P6-01：HTTP.sys宿主与配置

1. 验证Win7 HTTPS与真实浏览器安全握手；冻结HTTP API使用范围，旧系统不支持的接口不可静态导入。
2. 提供低权限应用接收器，URL预留/证书/防火墙由明确的本机配置步骤完成；应用管理员口令不自动获得OS权限。
3. 系统操作保存具体绑定、前值和项目所有权；只改本项目路径/端口，不修改全机共享IP监听表或覆盖其他服务证书绑定。
4. 默认关闭监听；管理员启用后只允许指定网络范围，禁用后停止新请求、失效会话及临时上传，并保留本地内容。
5. 请求总量/连接数/字节/上传并发有上限；超限快速返回，未认证请求不得无限占用密码派生或解码队列。
6. 静态文件使用打包清单映射，拒绝目录遍历、目录列举及任意文件读取，API路径不落到前端静态回退页面。

## 3. P6-02：配对与会话

1. 本地管理员解锁后主动开启短时配对窗口；一次性码有时效、尝试限额，应用重启/窗口关闭即失效。
2. 教师通过HTTPS提交配对申请，本地管理员确认教师名称和设备范围，防止仅知道短码就永久授权。
3. 服务端生成高熵教师授权，安全验证信息留本机，浏览器使用Secure/HttpOnly会话；长期配对凭据若支持持久化，须轮换、限期、可单独撤销，不放URL或静态JS。
4. 远程角色只能由本地授予，actor来自已验证会话；Host/Origin白名单、CSRF、SameSite、速率限制同时存在，不把“在校园网”当权限。
5. 教师撤销递增授权代次并失效相关上传/未提交命令；应用密码恢复或设备重置吊销全部配对，会话不能被旧备份复活。

## 4. P6-03：拟定API契约

以下为 `/api/v1` 契约草案；Rust实施时固定字段/错误码/版本测试，实际监听/端点逐项记录完成证据。

| 方法和路径 | 能力 | 请求/结果要点 |
| --- | --- | --- |
| GET `/status` | 限制公开字段/配对后扩展 | 服务/API/UI兼容版本，设备在线与有限状态；敏感状态需会话 |
| POST `/pairing/requests` | 仅配对窗口开放且限速 | 一次码/请求标识，返回待批准；不返回管理员凭据 |
| GET `/pairing/requests/{id}` | 该申请的临时凭据 | 只查询本人申请；超时失效；批准后安全建立会话 |
| POST `/session/logout` | 当前会话 | 显式注销账号，服务端递增该principal授权代次并吊销全渠道会话（本地锁定另用lock_local，仅撤本地会话），浏览器清理状态 |
| POST `/uploads` | publish:image | 流式上传、配额/类型检查，返回绑定教师/设备且短期有效uploadId |
| POST `/commands` | 对应发布/清空/撤销能力 | commandId、slot、expectedRevision、payload或uploadId；返回202及命令标识 |
| GET `/commands/{id}` | 本人或被授予结果范围 | 业务状态、提交/当前/实际显示修订、displayState及状态时间、错误码；不能读其他教师任意任务 |
| GET `/content-slots` | 授权设备/槽位 | 读取必要当前修订与预览信息，提交做冲突校验 |

不提供远程administrator万能端点。HTTP状态只反映请求层，command状态才代表业务进度。相同幂等ID不同负载为409类冲突，类型/时间/资源校验返回可定位错误；401/403不自动重复提交。

图片上传本身不发布；uploadId绑定主体/设备/期限/消费状态，不接受别人的uploadId。提交前再查权限和修订，文件准备完成时再查最新意图，防止上传期间被撤销仍生效。

### 作业与提醒API（P6-06）

| 方法和路径 | 权限与约束 |
| --- | --- |
| GET `/me/assignments` | 已登录，返回服务端任教班级/科目；不能由前端自填角色 |
| GET `/subject-profiles/{id}` | 仅本人授权profile或主管理员；仅返回必要只读预览/资源描述及修订，教师不获得布局写权 |
| POST `/commands` 的作业变更 | 教师仅本人且有效任教范围，强制ownerTeacherId及expectedRevision；教师profile/布局写命令拒绝，混入视觉字段整次拒绝 |
| GET `/resources/{id}/download` | 受控鉴权下载，不静态暴露ProgramData/他人原件；课堂列表取消thumbnail端点，独立图片预览接口另列 |
| GET `/classes/{id}/today-reminder` | 启用教师管理员/全局主管理员，同安装学校范围，服务器日期只读；过期或空正文返回空状态与当前修订 |
| POST `/commands` 的Send/ClearTodayReminder | 只允许可信Web origin，同安装学校的管理范围、服务器当天及提醒修订，不以提醒作者或任教班级限制；无未来日期/延长期限参数 |

配对必须绑定已存在账号，审批显示任教范围；不能配对时自选任课科目获得权限。主管理员通过本地批准的Web会话进入提醒页，仍需同源/CSRF/会话校验；不存在独立远程超级管理员万能接口。只开放提醒等明确用例。

Web页Readonly日期由白板返回；正文显示有效至当日23:59:59。跨日旧草稿提交返回REMINDER_DAY_CHANGED并要求主动核对，新日无提醒显示“今日暂无提醒”。清空/到期后桌面磁贴消失，新发送才恢复；Web不自行推算“已上屏”。本地写提醒在应用origin门禁拒绝；Web仅在会话/同学校受管范围/日期/修订全部有效时通过。

前端开放本人作业、本人课堂资料、共同今日提醒、授权语音播报四类业务模块，移除教师subject-layout编辑模块，保留全局BottomReminderAction；教师只编辑本人内容，共同提醒不按作者/本人任教班级限制。全局profile草稿、班级日提醒、带ownerTeacherId的日作业各自修订，避免互相无关冲突。磁贴响应式与本机布局规则由后端验证，浏览器预览不代替真实DPI/触控测试。

## 5. P6-04：React前端步骤

1. 在现代开发环境建立 `web/`，选择一个包管理器和锁文件，固定TS/React/Vite/Tailwind/shadcn兼容版本，不在Win7运行构建工具。
2. 将API契约落实到类型与运行时验证，api层统一处理401/403、版本不兼容、超时/冲突和取消，不把类型断言当JSON验证。
3. 引入按需shadcn基础组件，业务组件独立；优先系统字体/随包图标，不请求外部CDN。
4. 实现配对等待页和短时状态查询；会话只由服务端确认，页面刷新不伪造已登录。
5. PublishPage区分编辑草稿、图片本地预览、已上传uploadId、ACCEPTED和COMMITTED，展示隐藏/PPT状态而非误报上屏。
6. 一次发布生成一个commandId；超时先查询同ID结果，不能生成新ID自动重发。冲突提示刷新当前版本并让教师确认，不无条件重试覆盖。
7. 图片预览使用受限对象URL，替换/离页释放；限制浏览器一次载入的原图和列表，不因教师端非白板就放任内存泄漏。
8. 提供手机触控布局、清晰大按钮、键盘导航；组件尺寸/对比度/焦点和提示以实际教师设备检查。
9. 页面按需加载，首屏压缩JS+CSS目标≤512KiB、全静态资源≤5MiB；构建报告包含实际值，缓存/字体不隐藏在外部网络请求里。
10. 不引入Service Worker代投，离线只保留明确草稿；退出/撤销时清理敏感会话镜像，普通内容草稿留存策略告知教师。

Rust适配HTTP.sys接收请求后只建立可信actor并调用相同应用端口；不以通用serde JSON文档写入替代命令白名单。网络JSON与原日期/数字枚举/幂等指纹版本兼容，保持ACCEPTED/COMMITTED/displayState分离。现代Rust网络/TLS运行库不默认支持Win7；HTTP.sys/Schannel/依赖和教师真实浏览器的P0握手门槛不降低。前端技术栈不改语言，不在白板安装Node或嵌浏览器。

## Rust实施落点与完成条件

主责：fc-windows / fc-protocol / web；实施任务：P6-11/P6-01/P6-10。

## 第三十二轮切片：候选头完成与业务准入共用原期限
