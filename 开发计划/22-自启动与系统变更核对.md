# 自启动与系统变更核对

总计划 D11，2026-10-31；细化 P2-03／P2-04、C03、Q03／Q11。本文描述第二十一轮实现契约，实际构建、运行和清理证据见[实施进度记录](10-实施进度与验证记录.md)。Windows 7 SP1 x86、Windows 10、Windows 11 是分别取证的正式目标；本契约不代表三系统、希沃设备或真实注销登录验收完成。

## 期望、实态与明确确认

原生工作台的登录自启动页面显示已保存的期望开关、当前可执行文件的固定启动命令、新近读取的实际注册表状态及最近操作结果。开启、关闭、迁移 ZIP 路径后的修复均先显示复核，用户明确确认才提交。复核还捕获该次显示的目标命令；若当前程序路径在确认前变化，协调器在保存新意图和执行系统动作前拒绝，必须重新读取确认。字段不能提供执行路径、任意参数、注册表键或额外系统动作。取消复核不改变数据库和系统项；锁定、账号切换、工作任务取消后旧确认不得直接继续。

目标为当前 Windows 用户 HKCU Run 中本项目专属值。可信适配器从当前可执行文件得到规范本地绝对路径，完整加引号并追加固定 `--autostart`；不执行保存的旧命令或把路径交给 shell。拒绝网络路径、相对路径、目录穿越、ADS、嵌入引号、额外参数、控制字符以及不合规路径。采用保守限额：完整命令最多 259 个 UTF-16 单元，加终止 NUL 不超过 260；UTF-8 表示另限 1024 字节，超限整体拒绝，不截断。

读取区分不存在、可读取的有界 REG_SZ 命令、异常类型或长度的 Opaque 状态、读取失败。初始数据库使用 `Unavailable(NotObserved)`，不将未读取误写成关闭。异常或不可读取的实态不能作为系统变更的已确认基线。读取到其他路径时展示该事实，明确修复才替换；外部删除、策略变化和 ZIP 移动均不触发自动重建。

## 先记意图，再执行系统动作

SQLite 和注册表不是一个原子事务。唯一 writer 先保存 `Prepared`，再保存同一操作的 `Applying`，可信系统适配器随后核对原值、权限与任务存活状态，执行限定动作并读回，最后按真实结果保存 `Succeeded`、`Failed` 或 `NeedsReconcile`。系统调用期间不持有 Backend 锁，不持有 SQLite 事务。数据库回滚不表示注册表已回滚，未知结果不触发隐式重试或反向补偿。

注册表查询与写入并非原子 CAS：外部管理员或策略仍可能在原值查询与写入之间竞争。前像比较可以拒绝已观察到的变化，最终读回只证明该次观察时的状态；SQLite CAS 和本进程单任务所有权不能消除这个外部竞争窗口。适配器不会将前后检查描述为跨系统原子事务。

每个操作保存 command ID、持续递增序号、Prepared 文档修订、发起账号和认证代次、已确认目标开关／固定命令、先前实际值、阶段、最终读回、无秘密的分类原因以及适配器报告的物理变更标记。该标记用于保守结算；未记录 true 不证明中断期间系统从未变化，最终仍须以实际读回和阶段判断。整个自启动文档独立 CAS；复核后其他读取或操作推进修订时，旧复核必须重新读取。最多保留最近 32 条操作，序号高水位不因裁剪历史或重启回退。整个文档最多 64 KiB；Prepare 还预留最大 JSON 编码读回的结算空间，不能批准一个最终结果无法保存的系统操作。

页面读取、Prepare、Applying 均重新校验精确的当前本地主管理员会话、学校归属、账号启用、认证代次、口令状态与有效期；教师、用户、Web 会话不具备此能力。SQLite 真正 COMMIT 前再检查捕获会话及 JobContext 内存执行栅栏。取消是普通取消结果，不把正常取消误报为全局健康故障。提交后的系统调用使用独立的即时权限检查，持久 ticket 本身不授予执行 OS 动作的权限。

结算只接受当前已记录的完整 ticket；旧操作完成、伪造账号／代次、错误序号或错误 Prepared 修订不能修改新操作。持久的 Prepared 尚未授权物理调用，只能结算无物理变更的失败或取消；Applying 可在原会话过期或任务取消后记录已经发生的事实。成功必须具备目标状态的准确读回，未知值、读取失败、失败原因或目标不符不能成为成功。SQLite 结算失败时保留未完成操作，供后续读回核对，不能声称 OS 未变。

## 启动核对与外部漂移

独占部署启动或没有物理操作在途时，只读适配器读取本项目值，可信组合层按当前修订提交核对，不虚构登录身份。尚未完成安装初始化时不创建自启动设置，也不操作注册表。每个观察任务和变更任务共用物理所有权，取消请求不等于物理调用已返回；在途 Applying 不会被另一读取任务误当成启动中断。

崩溃遗留 Prepared 一律改为 NeedsReconcile。遗留 Applying 仅在准确读回已确认目标状态时记为事实已满足，否则 NeedsReconcile；核对始终不写注册表。已完成记录保持原历史，只更新新的实际观察；外部删除或旧路径导致期望与实际不一致时明确报告，由管理员重新确认关闭或修复。没有后台持续对抗系统策略的重建循环。

`--autostart` 沿正常启动恢复本地内容和已有部署，不弹设置，不自动解锁管理。重复启动继续遵守已有单实例规则；自动登录 Windows、系统服务、远程 OS 管理或 HTTP 写自启动均不在本入口授权范围。当前交付仍是带 CUI 诊断输出的开发探针；隐藏测试任务不证明实际登录时没有控制台窗口。正式 GUI 子系统打包和诊断输出策略、真实登录的前台影响均保留为发布前门槛。实际注销再登录验证开启和关闭、ZIP 移动、MSI 安装升级卸载仍需要各目标系统独立证据。

## Windows API 依据

[Microsoft Run / RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)说明启动命令长度上限及登录启动可能延迟；[RegQueryValueExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regqueryvalueexw)说明字符串不保证终止及缓冲区不足时的读取规则；[RegSetValueExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regsetvalueexw)说明写入 REG_SZ 应包括终止符。这些 API 文档不替代各目标系统实际运行证据。


## 第五十六轮候选实验：TxR 未满足严格前像比较，未合入生产

针对上述外部竞争窗口，曾在独立候选中实现同一事务绑定 HKEY 的读取、前像比较、暂存开启/关闭、关闭键、提交及实际读回；同时保持原任务截止和关闭失败 owner。候选编译、双严格 Clippy 与 GNU 静态导入检查通过，不能据此认定具备原子 CAS。授权 Win11 实际222项 Windows 适配测试为211通过、11失败：其中4项为独立COM路径候选失败，1项是本候选真实竞争反例，其余6项为自启动测试锁中毒派生；本模块24项实际17通过、7失败，不能称整套通过。

新诊断未改任何原断言，在独立进程精确运行普通竞争写测试，实际0通过、1失败、221过滤。输出明确：关闭操作在第2次新鲜性检查时，外部普通写入的open/set/close均成功；本候选随后仍返回无失败、物理修改true并将该替换值删除，原最终读回确实Absent。这是已读前像、尚未暂存删除的窗口，不能归因于关闭HKEY后的第3阶段。该方案没有提供本需求所需的读集比较保证，不以API名称或文档的笼统“事务”概念覆盖真实反例。
