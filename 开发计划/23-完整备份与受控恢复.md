# 完整普通备份与受控恢复

总计划 1.37 / D11，2026-10-31。落实 P2-05、M02/M03/M10 与 Q02/Q04/Q11。本文说明存储、文件和协调服务的实现契约；完整产品及 P2-05 尚未验收完成，实际测试、失败历史和清理以[实施记录](10-实施进度与验证记录.md)为准。

## 普通包与本机安全资料分离

既有 `StorageHandle::try_backup` 是可能含受保护凭据的本机 SQLite 恢复快照，不能直接供普通导出使用。普通数据库在全新文件中按严格业务允许列表重建，既不复制原始页，也不通过删除凭据行后导出旧 freelist。普通包不含口令或恢复码验证记录、登录限速、会话、配对材料、DPAPI 密钥、机器证书、语音原件与活动队列、可执行的旧系统操作 ticket。

教学投影覆盖学校、班级、科目、当前班级、默认教师和非授权账号显示标签；课表、单双周和保留历史；公共及科目布局、内容当前版和上一版；教师资料及资源目录；作业和适用提醒；校历教学事实与经清理的课堂、声音历史。账号显示名可以恢复；登录名、角色、停用状态、任教授权、强制改密、凭据及恢复码版本均以恢复前的当前安全状态为准。包内账号 ID 不创建可登录账号，也不重新授予教学范围。

学校及账号的数字 ID 不是跨安装唯一标识。首次创建主管理员时，在同一凭据事务中保存 CSPRNG 生成的公开安装标识；已有部署在独占启动的唯一 writer 中补建一次，损坏记录拒绝覆盖。清单、普通数据库和当前安装须一致。当前实现明确拒绝跨安装直接恢复；跨安装目录/账号显式映射与新凭据发放仍需独立流程。无恢复码时放弃全部当前部署走[独立重新初始化向导](24-无恢复码重新初始化.md)，不降低普通恢复的安装绑定。

## 格式、配额与一致性

`.fcbak` 是程序定义的单层无压缩流，不是任意 ZIP、CSV 或课表 JSON。固定 magic、版本、严格清单和顺序 payload 共同构成完整包。清单只接受 Database、Material、ProfileMedia 类型及相应稳定 ID；路径由可信代码生成，不接受包内路径。重复/未知字段、重复资源 ID、未知版本、溢出、缺失数据库、额外尾部、长度和 SHA 不符均拒绝。不同资源命名空间可以各有 ID 1。

清单最多 8 MiB，材料及内容媒体各最多 8192 项；原件合计沿用 2 GiB，单件及真实格式沿用原有规则。数据库另限 16 GiB，通过 `u64` 计数和 32 KiB 块流式处理。16 GiB 是新增备份政策，不是既有无限历史的理论容量证明；超限明确失败并保留原资料，绝不截断生成“成功包”。原件不整体读入内存，也不进入普通 4 MiB writer 命令队列。SQLite 自身另设值、行、SQL 等限制及执行进度取消回调；这些不是全部 pager 内存或物理文件 I/O 的硬实时上限。

唯一 writer 投影一致修订 R，并从该视图提取全部所需材料原件和内容媒体，包括 current/previous 的引用。文件服务持有数据库、原件与祖先目录的 pin，组合层在全量 pin 后再次核对 R 与当前会话，再逐项流式复制及验证。GC 已经移动或删除对象、修订漂移、取消或权限失效都拒绝本次导出。只发布完全成功的终名，取消清理自己的未完成包。不得只采样 revision 后复制未固定的原件。

## 预检、确认与当前安全底座

1. 在项目保护目录中解帧、校验实际字节/SHA、WIC 或 Office/PDF 真实格式、资源跨引用与联合配额。保持普通数据库及祖先 pin，预检期间不改正式资料。
2. writer 以只读方式打开普通数据库，拒绝 WAL、额外表/触发器/视图、非程序 schema 和非法业务文档；从当前安全状态构造隔离 preview，完成真实 startup 校验。preview 可能包含当前本机安全资料，始终留在保护 staging，不进入普通包。
3. 不可伪造的 `RestorePreview` 绑定实际输入数据库字节/SHA、清单、安装标识、媒体和预检时当前修订。确认前变化必须重新预检，不能用新的当前修订替旧预检背书。
4. 本机主管理员明确确认后，唯一 writer 先在原库持久递增全部当前账号授权代次与恢复代次，再发布权威。Web 会话关闭，普通接纳进入本进程不可逆的恢复状态；旧本地/Web/场景和准备任务失效，不颁发替代会话。
5. 等待共享 worker 的真实退出、音频 Closed 与停止代次确认及实际线程/原生所有权释放。取消和逻辑 Idle 不释放物理所有权。真实 HTTP 监听及在途 I/O 必须由组合层另行停止排空，不能以 `WebService::close` 代替；当前生产监听仍未交付。
6. 排空后才从最新当前库生成正式候选，保留此间结算的登录失败、当前凭据、权限和安全事实。全局修订、ID 分配器及其他安全高水位单向前进。普通 1024 mutation / 4 MiB 限额保持，完整候选通过 writer 专用流式 SQL 事务构造。
7. 最后关闭并实际 join writer，才能生成冷切换能力。文件服务同时核对候选路径、安装标识、来源、修订、恢复代次及候选实际摘要；预检普通数据库摘要与最终含当前安全资料的候选摘要分别记录。

源包旧 receipt 不恢复为操作权限或成功结果；当前已使用命令转为无正文、无授权的安全墓碑，避免换会话后重放旧命令。恢复不回退日期水位，不复活过期提醒；旧课堂运行证明失效，保留的历史只作审计。声音无旧原件或待播放队列，自启动和自动网络/抓取许可不因旧包重放。

## 三目录切换与启动核对

固定替换 `state`、`teachers`、`profile-content` 三树，保留根目录、现有密钥与 `runtime/instance.lock`。这不是多个 rename 的原子事务。冷切换在 writer、文件准备和音频已退出后计算完整 old/new 摘要，先写恢复日志及阶段事实，再逐次移动，保留完整旧集合；未知状态不自动开放网络。

启动先核对根 ACL、取得实例锁，显示首屏后在已有共享 worker 的期限/取消控制下核对恢复日志，再补全子目录 ACL、打开 Backend 和常规 GC。不能先创建空 state/teachers 掩盖中断。尚未完成的切换只恢复完整旧集合或验证完整新集合；缺记录却存在搬入的旧树、额外/篡改树、坏日志或其他歧义一律保留证据进入修复。终态清理可以中断重入，不让遗留完成日志误判之后正常写入。

原库在切换前已保存确认后的安全底线，因此退回 old 也不退回旧授权。工作区的 ordinary/candidate pin 必须先于工作区清理释放；取消 sealed candidate 同样清除自己的保护目录。实际 Windows 测试发现过此 Drop 顺序错误，失败及修复后结果分别留证。

当前自动化切点证明仅覆盖所测的进程/操作中断与文件观察，不等于真实掉电、磁盘控制器缓存或硬件故障验证。文件 flush、journal 和句柄 rename 也不能据此宣称多目录事务或全部断电情形自动恢复。

文件和 SQL 取消是块间、VM 进度点及阶段间协作检查。同步系统调用、磁盘 I/O 和终态目录清理不能据此声称可硬实时抢占；超时或取消期间继续持有实际物理所有权，直到调用和析构真实完成。

## 后续仍须完成

第二十二轮接通服务接口、启动核对及真实合成数据完整恢复测试链。第二十三轮接通主管理员工作台普通备份、保存副本与原生完整包选择、预检数量/范围复核、当前预检序列绑定的明确确认、锁定/取消时的大工作区后台回收，以及独立最终关闭协调器的进度/安全中止和完成后关闭入口。真实测试与仍未完成的设备验收以实施记录为准；跨安装映射和重初始化尚需继续实现。最终协调器不能复用已停止共享 pool 的旧 `JobContext` 栅栏；`PreparedRestore` 必须保留到正式候选生成，不能只留下其路径。

Windows 7 SP1 x86、Windows 10、Windows 11 均是正式目标。Win11 上的 GNU 构建、补充 Win7GNU 同机运行、Host 测试及静态 PE 检查分别留证，不替代真实 Win7/Win10、MSVC、希沃可见桌面/触控/PPT、正式 GUI 登录启动、安装升级和 72 小时验收。

句柄重命名使用 [Microsoft FileRenameInfo](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle) 对应的 [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)，不使用较新 Ex 类作为 Win7 保证。[Windows 缓冲 I/O 文档](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk)区分关闭文件与强制 flush；API 依据不替代实际断电测试。


## 原生交互与物理所有权

工作台只对本地主管理员显示完整备份恢复入口；共享 worker 在实际开始时捕获当前修订和精确本地 lease，写入/导出/预检及另存最终阶段重复检查。普通导出保留保护目录中的完整包，另存只接受原生选择器给出的不透明目标；32KiB逐块复制同时核对整包字节/SHA，在已固定的本地父链下新建随机暂存文件，以Win7可用的非覆盖句柄重命名发布。已有用户目标不覆盖，失败仅删除自己创建的对象，不打开或执行备份。

预检页完整显示所选位置、当前/备份修订、教学记录、数据库、材料与图片数量/字节，以及教学替换、当前安全资料保留、不恢复旧会话/语音和重新登录要求。超长位置分页显示而不省略；明确确认的内部Choice值绑定当前预检序列，旧页面已勾选的事件不能确认后来重新选择的包。只读显示字段不生成路径、清单、actor或恢复权限。

整个App只保留一个预检槽；取消、锁定、迟到结果或UI最后句柄释放仅标记回收，不在窗口线程递归删除大树。槽使用显式保留所有权，只有现有两worker中的真正析构完成才能复用。正常关闭先请求并完成槽回收，再关闭writer和共享执行池；没有额外常驻文件worker。

普通队列满时继续保留writer和双worker，重试提交关闭工作，不能直接停止执行池。成功关闭确认跨界面轮询保留，不能向已停止的pool重复提交关闭，也不能在缺少writer关闭证明时结束普通主泵；恢复退出则继续要求独立协调器的实际结束和结果确认。Windows上的Shell、声音、共享worker和最终协调器使用借用线程句柄的零等待`WaitForSingleObject`查询实际退出，再执行join；仅凭Rust的`JoinHandle::is_finished`不足以证明平台TLS析构完成。音频只有在实际退出并join后才能发布Closed，逻辑完成或已确认停止代次期间仍显示Stopping。相应回归持有真实TLS析构及实际双worker/满队列，并在实际关闭后再轮询，释放前不得提前加入、开替代线程或声称关闭完成。

零超时查询行为和最低系统版本依据[Microsoft WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)。TLS回归提前启动并握手检测线程，持有析构期间只检验回收调用的返回，释放后才join检测线程，避免把loader-lock下的新线程入口/退出阻塞误当成回收调用阻塞；相关平台约束见[Microsoft DLL最佳实践](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-best-practices)。这些API依据不替代实际Win7/Win10测试。

确认的耐久能力保留在该槽，不以JobTicket结果为唯一所有者。即使取消或锁定恰逢屏障COMMIT后、普通worker丢弃返回值，主泵仍会检测不可逆状态并接管。Shell准备域先停止并真实结束，唯一共享pool和audio再转交独立最终协调器；协调器仅在物理排空后生成当前安全候选、关闭writer、封印并切换。确认屏障后失败而未产生能力时走仅排空并关闭原库的路径，不构造假恢复许可。同步调用或线程故障导致物理所有权不明时保留Retained和操作位；可请求中止，超时只终止本程序并留待受控启动核对，不提前声称释放或重开管理渠道。

旧摘要辅助函数曾套用普通资料50MiB上限；恢复数据库现使用独立16GiB许可下的32KiB流式摘要，并为完整导出记录实际整包SHA。材料与图片自身限额没有扩大。超过50MiB的回归仅证明所测大小和取消检查，不等于16GiB全容量、全部内存分配或硬实时期限证明。
