# 课表角色交换与活动拆合

总计划1.32 / D11，第十九轮，2026-10-31。落实P4-02、P4-03及Q05中角色交换、共用活动拆合与作息类型变更确认。本文记录当前实现契约；构建、Host测试、Windows实际运行与可见白板验收分别见[实施记录](10-实施进度与验证记录.md)，不提前声明整项完成。

## 身份与操作范围

原生“课表、作息与校历”仍由本地主管理员管理，教师Web没有新增课表写接口。活动是`RowKind::Activity`作息行，以`enabled_days[7]`表达适用星期；它独立于课程格、科目与任课老师。

四个纯草稿操作定义于`fc-domain::schedule_document::ScheduleDocument`，返回完整新文档或带位置的错误，调用者原文档保持不变。

| API | 行为 | 身份处理 |
| --- | --- | --- |
| `swap_table_roles(semester_id)` | 仅在恰好一张Odd、一张Even时交换角色 | tableId、rowId、logical_key、顺序和全部内容不变 |
| `split_activity(semester_id, table_id, row_id)` | 至少启用两个星期的活动，拆成每个启用星期一行 | 所有结果重新分配physical rowId与logical_key；原活动行退出当前表 |
| `merge_activities(semester_id, table_id, row_ids)` | 合并2至7条兼容活动，放在原最靠前所选行的位置 | 合并结果重新分配physical rowId与logical_key；全部被合并行退出当前表 |
| `convert_row_kind(semester_id, table_id, row_id, kind)` | 类型必须实际改变；非课程结果移除课程格及其教室、备注 | physical rowId和原行名称保留，logical_key重新分配 |

交换角色不移动课程或作息，不更改第一教学周周一。单双周解析随后按新角色选表，学期、实际授课日期和作息时间算法保持原契约。

全部新编号来自`allocate_id`，高于整份文档中当前行、保留历史及持久高水位。溢出明确拒绝；拆合退出的行编号不能分配给新行。各操作不更改`dual_history`，也不以草稿变更增加已保存修订。

## 无损活动拆合与双表原子性

拆分后各行星期集合互斥，并集与原活动相同；时间、分组、活动类型和名称逐行保留。随后可单独修改某日活动。课程、休息行不参与活动拆合。

合并要求所选活动时间、分组和各表自身名称一致，每行至少启用一个星期，星期集合互不重叠。不同名称、时间、分组或重叠星期明确拒绝，不选择其中一个值丢弃其余内容。未选作息行的内容及相对顺序保留。

`timing_sync=true`且有双表时，通过原logical_key查找另一表的对应行，严格核对所操作行的类型、时间、分组和适用星期。任一对应行缺失或不兼容，整次操作失败，不留下半张表的修改。两张表的新physical rowId不同，对应结果共享同一个新logical_key。

两张表允许各自使用不同活动名称：拆分分别复制各表名称；合并分别检查每张表内部名称一致并保留。作息同步不扩大为名称或课程同步。关闭同步时，只操作选中的表。

## 原生确认、取消与锁定

1. 角色交换在周表页发起；活动拆合从已有活动行进入。先应用本行尚未保存到草稿的名称、时间和星期，再发起拆合，避免使用旧值。
2. 拆分先展示结果数量、适用星期和单表/双表影响；合并先选择另一兼容活动，再展示影响。原生入口每次合并两行，可重复合并；领域API同时接受2至7行。
3. 类型变更展示受影响各表原课程的星期、科目、老师及教室/备注字数，并列明本次目标类型、时间、分组、适用星期和名称。转为非课程会清除这些课程格及元数据；转回课程不会恢复旧正文。
4. 确认页持有本编辑器的不可变候选；确认只替换内存草稿，其他编辑事件不能悄悄修改待确认候选。拆合确认后返回周表，不继续使用已经退出当前表的旧行选择。
5. 取消本次变更恢复原编辑页及其有界非秘密表单，文档不变。锁定保留候选及原表单；只有原主管理员重新登录可继续该编辑器。其他账号不能借用原候选。
6. 最终仍需“保存全部”。后台唯一writer再次核对精确本地会话、权限、预期修订、科目与任教引用，整份提交；冲突不自动覆盖。确认页不授予保存权限，也不绕过CAS。

类型变更时，本次表单的行名称只修改当前表；另一表原有名称保持。同步的时间、分组、类型与适用星期继续按既有规则成对应用。无关半成品日期、时间或校历草稿不阻止上述纯编辑操作，最终保存仍执行完整校验。

## 网格、容量与保存格式

部分星期适用的活动/休息行按七个星期格显示，不适用格明确标注；只有全部星期启用的非课程行才跨列显示。拆成逐日活动后，网格不会把一天活动误画成整周共用。

继续使用当前`ScheduleDocument`、课表codec和既有数据库事务，不新增schema或crate，保持十二crate及既有依赖方向。单表最多128行、全聚合最多4096行，保留历史也计入容量；拆分达到上限明确失败，原草稿完整保留。

整份课表及历史编码仍受64KiB单值上限约束。元素上限不保证任意组合都能持久化；编码超限明确拒绝，不截断、不隐式迁移，保留内存草稿供调整。草稿及待确认候选仅保留在当前进程，不能据此承诺崩溃后恢复未保存编辑。
