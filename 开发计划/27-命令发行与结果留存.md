# 命令发行与结果留存（D11 实施细则）

2026-11-02。与同批实现源码核对，细化 D11 既有命令幂等、未知结果与有界留存规则，不新增任务编号或权限。本篇覆盖[教师内容](12-教师内容API契约.md)、[课堂资料](13-教师课堂资料API契约.md)、[教师语音](15-教师语音API契约.md)中旧的浏览器随机 commandId、正常 schema1 写入和仅 numeric ID 的新命令查询说明。URL 前缀仍为可信部署的 `api/v1/`；schema2 是命令封装版本，不是新的 API 路径。实现范围不代表测试完成，验证状态单独见[实施进度](10-实施进度与验证记录.md)。本文源码引用均为仓库相对路径与函数；本轮实际验证使用固定 S9 输入，整合、运行及平台边界以实施记录为准。

## 发行与完整命令身份

普通教师业务先通过当前认证连接调用：

```http
POST api/v1/commands
Content-Type: application/json
X-FC-CSRF: <当前精确 CSRF>

{"schemaVersion":2,"family":"content"}
```

family 仅接受小写 `content`、`materials`、`voice`。请求严格只有 schemaVersion/family，拒绝重复、未知字段、其他 family 和客户端自带 ID；该请求正文上限128字节。沿用真实同源 HTTPS、Host/Origin、Cookie、精确 Web lease、CSRF、当前账号/学校/权限检查；发行本身不授予任何业务操作权限。

成功为 HTTP **201**，JSON 恰有六个字段：

```json
{
  "schemaVersion": 2,
  "status": "ISSUED",
  "family": "content",
  "commandId": "123456789",
  "commandTicket": "c2:11111111111111111111111111111111:1",
  "expiresInMillis": 86400000
}
```

示例值只说明格式。commandId 是服务器产生的非零规范 u64 十进制**字符串**，不能转为 JavaScript Number；浏览器不得自己生成或替换。commandTicket 为 `c2:<epoch>:<serial>`：epoch 是32位小写 hex、解码后非全零；serial 是无前导零的非零十进制，最大 `9223372036854775807`。二者组成完整 pair，任何提交、重放核对和历史查询都保留原 pair；不能只保留 raw commandId、只凭 ticket 或换一个 epoch 查相同 raw ID。

唯一 writer 核对实际发行记录、期限、family 与 CommandOwner。当前 owner 绑定为 principal、school、authEpoch、origin，family 是另一个必须匹配的发行字段；**没有设备 ID 的票据绑定**。每次传输仍重新认证本次精确设备 lease，业务中的上传、目标和 owner 也保留原检查。不得把 owner 描述为“相同设备才有权”，也不得反过来把拥有 pair 当作会话或权限凭据。

源码：发行协议与六字段响应：`crates/fc-protocol/src/web/command_window.rs` `issue/issued`；ticket/owner/上限定义：`crates/fc-ports/src/command_window.rs`；真实发行和作用域：`crates/fc-bootstrap/src/backend/command_window.rs` `issue_web_command/resolve_web_command/begin_command_scope`。

## 写入与历史查询

正常新命令的写 DTO 为平铺 schema2，增加 commandTicket，保留原业务字段和原指纹规则：

| 业务 | POST 路径（相对 api/v1/） | 完整请求字段 |
| --- | --- | --- |
| 作业、提醒 | 原 `content/homework/...`、`content/reminders/...` | `schemaVersion:2, commandTicket, commandId, expectedRevision, text` |
| 资料追加 | `materials/folders/{ownerTeacherId}/{subjectId}/append` | `schemaVersion:2, commandTicket, commandId, uploadId, allowedClassIds` |
| 资料删除 | `materials/folders/{ownerTeacherId}/{subjectId}/delete` | `schemaVersion:2, commandTicket, commandId, materialId, resourceVersionId, expectedMaterialRevision` |
| 播放提交 | `voice/broadcasts` | `schemaVersion:2, commandTicket, commandId, assetId, expectedAssetRevision, classId, repeatTotal` |
| 停止任务 | `voice/broadcasts/{jobId}/cancel` | `schemaVersion:2, commandTicket, commandId, jobCommandTicket, expectedRevision` |

commandTicket 必须是原非空字符串；schema2 缺失/null 或 schema1 混入 ticket 都拒绝。停止请求的 jobCommandTicket 是另一个字段，其显式 null 仅用于原来确为 legacy 的任务，详见下节。对象 ID、资源版 ID、上传 ID 仍是对象身份，不得拿发行 commandId 替换它们。

写成功响应外层为 schemaVersion2，回显原 commandTicket/commandId；内容、资料及语音分别保留原 COMMITTED、CANCEL_REQUESTED 状态和业务结果。嵌套 CONTENT、资料 record 等业务结构不因此改版。原业务 payload、目标、CAS、正文原始值与 actor 指纹规则不变：同一原意图的重复调用读取原结果，不二次写；同 pair 换 payload、操作种类或其他不匹配用法拒绝，不能把一个 family 的票据转给另一 family。客户端仍不得自动重发 POST。

三个历史查询路径固定为：

```text
GET api/v1/content/commands/{commandTicket}/{commandId}
GET api/v1/materials/commands/{commandTicket}/{commandId}
GET api/v1/voice/commands/{commandTicket}/{commandId}
```

路径使用原规范 ticket/ID 文本，不作大小写、前导零或编码别名归一化。成功响应为 schemaVersion2、status COMMAND_RESULT，回显完整原 pair；state 为 COMMITTED 或 NOT_FOUND，并带原业务结果或 null。当前认证、owner/family、票据期限及各业务原有日期/范围权限仍要通过。有效发行但尚无结果才是 NOT_FOUND；它不证明排队执行永远没有发生，不能据此重发。

另一 owner、错误 family 或不匹配 pair 的查询不进入原业务结果披露，而是 COMMAND_NOT_ISSUED；主管理员也不能凭这个端口跨账户读 receipt。当前内容 GET、资料目录 GET、刷新页面或查询当前任务，仅说明当前业务状态，**不能确认原命令结果或清除其 RESULT_UNKNOWN**。必须查询匹配原 pair 的历史结果；历史 COMMITTED 同样不说明当前槽、目录或任务仍是原版本。

源码：内容写与查询：`crates/fc-bootstrap/src/web_application/content.rs`、资料写与查询：`crates/fc-bootstrap/src/web_application/materials.rs`、平铺资料 DTO：`crates/fc-protocol/src/web/materials.rs`、外层命令响应绑定：`crates/fc-protocol/src/web/command_window.rs` `bind_response`。

## 语音提交、停止与当前任务分别绑定

播放 submit 的 pair 标识该提交；任务 jobId 等于原 submit 的 commandId。当前任务对象额外携带 `job.commandTicket`，值为**原 submit ticket**，只有明确存量 legacy 任务才为 null。当前任务列表和状态响应为 schema2。

新任务当前状态读取使用：

```text
GET api/v1/voice/broadcasts/{jobId}/commands/{originalSubmitTicket}
```

任务取消另外发行一个 voice pair。取消请求的 commandTicket/commandId 是**本次 cancel** 的身份，jobCommandTicket 是目标任务的**原 submit ticket**，expectedRevision 仍固定原选择的任务修订。取消成功响应的外层回显 cancel pair，内层 job.commandTicket 仍是原 submit ticket，不能互换；查询取消命令结果使用 cancel pair 的 `voice/commands/...` 路径。不得仅凭复用的 numeric jobId/修订把新取消重新绑定到其他任务。

当前任务身份关联独立于客户端命令留存窗口：历史票据到期不表示一个原生播放 owner 已归还。当前状态路径核原任务关联和当前真实权限，不用它续原命令期限或重新提交；旧 numeric `voice/broadcasts/{jobId}` 只用于关联为 null 的 legacy 任务，不能在 v2 关联查询失败后降级。排队/COMMITTED、停止请求/STOPPING 也不等于实际播放、已听到或物理 Released。

源码：submit/cancel 解析：`crates/fc-protocol/src/web.rs` `voice_submit_window/voice_cancel_window`；响应和原 job ticket：`crates/fc-protocol/src/web/voice.rs` `status_bound/committed_window/cancelled_window/command_outcome`；语音 HTTP 分发：`crates/fc-bootstrap/src/web_application/voice.rs`；当前任务与历史结果分别核验：`crates/fc-bootstrap/src/backend/voice.rs` `status_bound/command_outcome/submit_window/cancel_window`。

## 明确拒绝与未知结果

错误封装仍沿用 `{schemaVersion:1,code}`，不能因命令成功外层为 schema2 就改写所有错误版本。

| HTTP | code | 含义与客户端处理 |
| --- | --- | --- |
| 410 | `COMMAND_EXPIRED` | 原命令已到期、已退休或被明确业务回收。停止这个旧操作，不续期、不自动换 ID 重试。 |
| 404 | `COMMAND_NOT_ISSUED` | 没有匹配发行，或完整 pair/owner/family 不符。明确拒绝，不能作为 UNKNOWN 重发。 |
| 503 | `COMMAND_WINDOW_FULL` | 有界命令留存容量不足；明确拒绝，不扩大留存或自动发行重试。 |
| 503 | `COMMAND_WINDOW_UNAVAILABLE` | 无法证明窗口时钟/期限；明确拒绝，不当作写入结果未知。 |
| 503 | `RESULT_UNKNOWN` | 原写入/COMMIT 或响应交付不能确定。只保留原 pair、原目标与 payload，按用户动作查询原历史结果；不自动重放。 |

格式错误仍为400 INVALID_REQUEST，认证/权限仍为401/403，原 CAS/日期/指纹冲突仍为409及各业务确切 code；普通路径不存在404 NOT_FOUND 也不等于 COMMAND_NOT_ISSUED。收到“过期”只说明不再接受/披露原命令，不能反推过去未写入。用户若明确开始新意图，应先重新核对当前目标、权限、日期和修订，再发行新 pair，不恢复旧操作。

前端未知状态仅在内存持有完整 pair 与原意图，不写浏览器持久存储；查询本身不发行命令、不续期、不自动重发业务。401/403、注销、撤权及导航继续执行各业务既有敏感状态清理和未保存提示，不以恢复旧票据绕过新授权。

源码：HTTP 错误映射：`crates/fc-bootstrap/src/web_application.rs` `command_failure`；错误线格式：`crates/fc-protocol/src/web/responses.rs`；writer 完整核验：`crates/fc-storage/src/command_window.rs` `check_at`。

## 留存上限与真实 owner

命令窗口从原发行起最多 **24小时（86400000毫秒）**。读取、查询、刷新、重绘、排队和重复请求都不能续期；服务端使用持久逻辑时钟与真实单调样本核期限，时钟回拨/epoch 退休不重新开放旧命令。expiresInMillis 是窗口长度说明，不是浏览器可自行延长的授权时间。

全窗口有 **65536条、64MiB** 的计费上限，覆盖发行记录、原结果/索引/计费元数据，并计入尚未物理回收的旧记录；不是每 family 各有一份，也不是整个数据库或进程 heap 上限。业务结果和所属命令计费在同一 SQL COMMIT 内闭合，容量失败不能留下未计费的成功写入。先持久退休边界，再按固定小批次回收；已退休但尚未删除的数据仍不接受新执行并继续计费。

**TTL 不是 owner 归还证明。** 原接受的准备、下载/抓取、音频、文件/原生句柄等资源必须按各自真实完成与负向收尾流程归还；逻辑取消、客户端过期或页面离开不能伪造物理完成。持有原 owner 的窗口记录保留计费，普通 GC 不删 held 记录；负向结算只能使用原闭合 owner/关联，不能靠 raw ID 重新寻找或重新发行票据。语音策略等先有持久 intent 再执行原生停止的操作，Pending 历史结果只能保持未知，不能驱动第二次执行；当前配置读取与原历史结果分开。

语音还有原有更窄的业务审计规则：最多100个终态任务，终态保留最长24小时；并非每张票据都保证保留满24小时。业务 prune 可能因条数或终态年龄更早删除原任务及其 submit/cancel 回执，并原子退休对应命令关联；之后历史/重放返回 COMMAND_EXPIRED，不会因回执已删再次创建任务。它不退休无关的 held owner，也不把仍活动的任务当作过期客户端资源释放。 终态年龄按实际 ended_at 判断，提交 sequence 仅作同秒稳定排序，不代替完成时间；新取消的结果保留至本次事务提交，超额时清理其他旧终态，仍不超过100条。

源码：窗口维护、计费与 held 回收条件：`crates/fc-storage/src/command_window.rs` `maintain/register_documents/register_journal/sync_profile_content_owners/sync_owner_holds`；语音审计上限及维护：`crates/fc-domain/src/voice.rs` `MAX_VOICE_AUDIT/AUDIT_TTL_SECONDS/maintain`；语音 prune 与命令关联：`crates/fc-storage/src/business/voice.rs` `prune/command_window_pruned_jobs` 和 `crates/fc-storage/src/command_window.rs` `sync_voice_bindings/retire_voice_receipt`。

## 保留 schema1 的范围与存量兼容

本次只替换**命令身份、写入封装和命令结果留存**。原配对/会话、内容范围与当前 CONTENT、资料目录/班级分页、资料上传预留/字节/取消、语音 capabilities 和 VOICE_UPLOADED 等 DTO，继续按各自现有 schema1 格式。语音任务列表/当前状态明确使用本篇 schema2。不能把所有 POST（例如配对和上传预留）都机械改成命令 schema2。

解析器保留部分旧 schema1/numeric 路由用于已存在资料和回执的受限兼容，**不代表正常新写入可继续自造 numeric commandId**。writer 对没有 v2 作用域的旧命令，只允许数据库边界已冻结索引中的真实既有回执及其原结果匹配；没有索引、缺原主回执、超过原不续期宽限或已退休，都拒绝。旧资料目录/资源本身按原数据规则继续读取；旧回执的 allowlist 不新增、不因读取或重启刷新期限，也不从备份或客户端请求补造“已发行”。不能在 v2 失败后降级到 schema1/numeric 路径，也不能把存量索引当作任意新写许可。

源码：旧回执边界索引与不续期宽限：`crates/fc-storage/src/command_window_legacy.rs` `open/check/maintain`；writer 无 scope 的旧命令门：`crates/fc-storage/src/lib.rs`；固定路由与版本解析：`crates/fc-protocol/src/web.rs`。
