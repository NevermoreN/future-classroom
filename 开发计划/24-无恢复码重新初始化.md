# 无恢复码时清除本机资料并重新初始化

总计划 1.37 / D11，2026-10-31。落实 P2-01 第8步、P2-05 与 Q02/Q11。此流程放弃当前部署的数据与身份；它不恢复密码，不给旧账号增加权限，也不代替[普通完整备份恢复](23-完整备份与受控恢复.md)的同安装校验。实际完成范围及验证结果见[实施记录](10-实施进度与验证记录.md)。

## 进入、确认和权限边界

登录页、恢复码页和数据修复页提供本机清除向导入口。入口先走原程序的正常关闭链，等待实际音频、共享任务和唯一 writer 关闭，再退出持有实例锁的作用域。随后运行当前程序的 `--repair`。异常关闭、无法证明物理退出或独占锁仍占用时，不允许用“没有 Backend”推断可以清除。

`--repair` 是独立的原生修复窗口，使用原有固定双 worker 模型。它验证当前 Windows 部署用户的根目录权限并持有原位实例锁，不打开教学数据库、解密旧 DPAPI 密钥或启动声音、Shell、教师 Web。进程内的原子登记按真实部署根对象身份记录 Backend 打开和修复声明；已经开始打开旧库的进程不能再领取“从未打开”的证明，修复声明成功后排队的 Backend 打开也被拒绝。条目数量有界且不在同进程回收；文件身份复用只允许产生保守拒绝。

该入口以当前 Windows 部署目录的实际访问权为边界，不接受网络或备份包提供的角色字段，不以万能密码绕过账号。无密码进入只允许明确放弃当前全部本机部署，不能进入旧教学资料管理。正常登录和恢复码恢复仍使用原认证、权限与限速。

向导先显示清除范围，再在 worker 核对固定命名空间和准备独立操作目录。准备成功后，用户须分别确认“放弃全部本机资料”和“关闭程序、重新启动并创建新学校及主管理员”。两项默认均未确认，确认值绑定本次非零复核序号；旧复核、未知字段、部分确认和重复确认不能授权清除。取消关闭向导；后续正常启动仍须原账号认证。

## 清除范围

保留数据根目录与 `runtime/instance.lock`，不重命名整个根。仅以下13个程序拥有的根目录参与切换：

| 目录 | 当前资料 |
| --- | --- |
| `state`、`config` | SQLite、学校账号、口令和恢复码记录、DPAPI密钥及部署标记 |
| `teachers`、`profile-content` | 教师材料及独立文字/图片所引用的本机原件 |
| `voice` | 本机语音原件与活动资料 |
| `exports` | 当前部署目录内导出的备份 |
| `staging`、`launch-copies`、`web-material-staging`、`open-copies`、`quarantine`、`cache`、`recovery` | 本部署暂存、打开副本、缓存及普通恢复状态 |

旧树缺失须明确记录，不凭空创建“旧数据”。未知根条目、重解析点、硬链接或无法确定所有权的布局拒绝操作并保留证据。旧 SQLite 或密钥可以为空或损坏；文件检查读取原始字节与对象身份，不要求解析旧库或解密旧凭据。准备阶段不修改上述正式树；健康旧进程关库期间的合法 checkpoint 不以旧预检摘要误判。

已另存到部署目录外的副本不在清除范围。Windows 登录、现有自动启动值、网络配置、SSH 授权和其他应用不被修改。新数据库不把原自动启动变更记录、配对或旧系统操作当作新授权；已有系统配置以后仍须按真实回读核对。旧包仍受原安装绑定检查，不能仅因学校或账号数字 ID 相同就直接恢复到新安装。

## 实际关闭与有日志的切换

确认只提交一次；最终执行线程在交接共享 pool、准备能力和“从未打开”证明前创建。窗口停止普通接纳，实际任务结束和 Windows OS 线程终结检测、join 完成后，才能产生独立且不可 Clone 的冷重新初始化许可。逻辑取消、空的 UI 任务槽、Rust 线程结果已发布和 `Option<Backend>::None` 均不构成证明。

文件服务使用独立的 `reinitialization` 命名空间、固定 owner 标记、随机操作名、保护 ACL 及根/运行目录 pin。得到实际冷许可后才记录最终旧树原始摘要与身份。切换使用非覆盖的源句柄重命名，并核对原对象身份；普通恢复 manifest、`ConfirmedRestore` 或数据库凭据不作为重初始化许可。

启动核对顺序为：验证根权限和取得实例锁 → 重新初始化日志核对 → 普通恢复日志核对 → 常规目录补齐 → DPAPI/数据库打开。不能先补建空树掩盖中断。提交前中断按独立日志恢复完整旧集合；提交后完成新空集合及受控旧资料清理后，才允许首次注册。坏日志、摘要不符、缺失凭据对象的歧义组合或未知文件布局进入 Repair，保留现有证据，不自动解锁或重新注册。

清理在 worker/最终执行器进行，按已验证的程序目录与对象处理，不使用生产路径的 `remove_dir_all`，不跟随重解析点。取消先关闭准备槽的发布接纳，再撤销任务；迟到准备由其原 worker 回收，不能因为另一 worker 曾看见空槽就释放仍运行的所有权。未知实际线程结束或关闭失败保持 Retained。

旧对象清理清单记录相对 UTF16 名称、原卷/文件身份、类型、长度和原始 SHA，并由切换日志绑定清单本身的长度与摘要。提交后允许已删除对象缺失；剩余对象必须为原清单子集，每次删除仍对同一个独占句柄复核身份和实际字节。全部旧数据对象移除后才写独立终结记录，最后清理已验证的元数据和终结记录。缺失或损坏清单不能授权删除剩余旧数据。

当前每棵树最多100000个对象、每目录32768项、深度64、相对名16000 UTF16单元；旧清理清单编码合计32MiB，单次目录路径分配合计32MiB。原文件用32KiB分块读取，没有借用普通备份的16GiB上限而截断。超限、取消或不可读时明确停止并保留，合作取消不代表可以硬抢占同步磁盘调用。没有待处理重新初始化操作时，普通启动不套用本流程的破坏性操作目录白名单。

重新初始化专用目录创建及 ACL 回读使用 Win7 已有的 Unicode extended local DOS 路径：先验证并 pin 原本地父链，再取得已固定父目录的规范磁盘路径，仅追加固定末级名，不直接给任意输入加前缀。它不依赖系统长路径策略或应用 manifest；超过传统 248/260 字符边界的候选目录另有实际准备/取消回归。普通资料和普通恢复的既有路径检查保持原约束。

## 重启及验收

本进程完成清除后关闭。后续独立启动正常程序才创建新的 DPAPI 密钥、空数据库，并走已有的学校/主管理员首次设置事务，生成新的公开随机安装标识。旧账号、旧恢复码及旧设备配对不迁入。没有对旧资料的自动读取或恢复入口。

要求分别取证：真实取消精确保留、默认/部分/陈旧确认拒绝、损坏或零字节数据库与密钥、逐重命名中断与再次核对、坏日志及链接拒绝、实例锁持续排他、独立程序重启与新密钥/新安装标识、旧包直接恢复拒绝、外部另存副本保持及本轮测试完全清理。合成故障切点与隐藏控件不等于硬件断电、可见希沃交互或真实 Win7/Win10 的兼容证据。跨安装目录与账号显式映射仍单独推进，P2-05和完整产品不能据此标为完成。
